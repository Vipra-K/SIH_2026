# BorderSight AI — Current MVP API

This document describes the API currently implemented by the Phase-2 MVP. It intentionally avoids documenting planned endpoints that are not implemented yet.

## Health

`GET /api/health`

Returns the backend service status and version.

## Dashboard

`GET /api/dashboard`

Returns dashboard counters and sector summaries:

- camera totals and online count
- active and critical incident counts
- today's event count
- sector status summaries

## Cameras

`GET /api/cameras`

Returns the built-in MVP camera list (`CAM-01` through `CAM-04`).

> Note: the repository also contains a camera-source router under `/api/cameras` for adding/removing local/video/RTSP sources. The two camera models are still being consolidated; do not treat the source-management API as the canonical dashboard camera model yet.

## Incidents

`GET /api/incidents`

Optional query parameter:

`status=UNRESOLVED|ACKNOWLEDGED|RESOLVED`

`GET /api/incidents/{incident_id}`

Returns one incident or `404` when it does not exist.

`PATCH /api/incidents/{incident_id}/status`

Request body:

```json
{"status":"ACKNOWLEDGED"}
```

Supported statuses in the current backend:

- `UNRESOLVED`
- `ACKNOWLEDGED`
- `RESOLVED`

## AI events

`POST /api/events`

Example request:

```json
{
  "camera_id": "CAM-01",
  "object_type": "PERSON",
  "track_id": "P-021",
  "confidence": 0.96,
  "crossed_restricted_boundary": true,
  "loiter_seconds": 90,
  "toward_border": true,
  "low_light": true
}
```

The current transparent risk model adds:

- restricted-zone crossing: `+50`
- loitering for at least 60 seconds: `+20`
- movement toward border: `+20`
- low-light condition: `+10`

Events below a score of `30` do not create an incident. Higher scores are mapped to `MEDIUM`, `HIGH`, or `CRITICAL` severity.

## Zones

`GET /api/zones`

`POST /api/zones`

Example request:

```json
{
  "name": "Restricted North Zone",
  "camera_id": "CAM-01",
  "points": [[0.1,0.2],[0.8,0.2],[0.8,0.8]],
  "severity": "HIGH"
}
```

`DELETE /api/zones/{zone_id}`

The current zone API does not yet implement the previously planned camera-scoped zone paths or `PATCH /api/zones/{zone_id}`.

## Video processing

`POST /api/video/upload`

Uploads a supported video (`mp4`, `webm`, `mov`, `avi`, or `mkv`). The MVP limit is 500 MB.

`GET /api/video/jobs`

Lists video-processing jobs.

`GET /api/video/jobs/{job_id}`

Returns the status and progress of a processing job.

`GET /api/video/jobs/{job_id}/mjpeg`

Streams the annotated JPEG frames generated by the shared inference pipeline using an MJPEG response.

## Realtime events

The current realtime API uses **Server-Sent Events (SSE)**, not WebSockets.

`GET /api/stream/events`

The stream first emits a connection event and then publishes `border-event` messages containing detection/incident data.

`GET /api/stream/heartbeat`

Returns a simple stream readiness response.

## Current architecture notes

The current MVP uses in-memory stores for cameras, incidents, video jobs, zones and realtime subscribers. These are suitable for the SIH demo but are not durable across process restarts.

The incident lifecycle currently implemented by the backend is:

`UNRESOLVED -> ACKNOWLEDGED -> RESOLVED`

`INVESTIGATING` is a future workflow state and is not currently part of the API enum.
